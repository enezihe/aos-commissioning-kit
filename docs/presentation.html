Hands-on engineering project

AOS Commissioning Kit

Deploying, configuring and troubleshooting a mini Airport Operational System on Kubernetes and OpenShift.

Python · Docker · Kubernetes · Helm · OpenShift · AI-assisted log analysis

Purpose

What this project is for

An implementation engineer's day is not only writing code. It is deploying, configuring, validating, diagnosing and explaining.

  • Practise the full delivery loop: build, containerize, deploy, configure, verify, troubleshoot, document.
  • Work the way a commissioning project works: stage gates and readiness criteria before go-live.
  • Build hands-on fluency with container platforms, not just theory.
Scenario

A fictional airport goes live

A small operational system is installed for an imaginary airport. Each component mirrors a real integration point.

Flight service

Airport-database style API: flights, gates, status updates.

FIDS consumer

Reads flight events for information displays.

Baggage simulator

Baggage handling subsystem that depends on gate and flight data.

Config pack

Gates, stands, carousels and airlines as validated definitions.

Progress

What works today

The flight service runs as a container image and answers the full API.

EndpointBehaviour
GET /healthLiveness check, used later by Kubernetes probes
GET /flightsList flights
POST /flights201 on create, 409 if duplicate, 422 on invalid body
PATCH /flights/{no}Update gate, 404 if the flight does not exist

Known limitation: data lives in memory and is lost on restart. This is the starting point for a Phase 2 discussion on stateless pods.

Way of working

How the project is built

  • One Git branch per phase, small commits with conventional prefixes (feat:, docs:).
  • Every phase ends with a short self-check on the concepts behind it.
  • Failures are treated as material: each broken state becomes a troubleshooting exercise.
  • Documentation is written as the work happens, not afterwards.
